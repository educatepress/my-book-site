## ★自動生成の状態(2026-09-28 訂正)

「2026-09-26に自動生成を停止」と書いていたが、**止まっていたのは Vercel Cron の
daily-publisher / auto-generator だけだった。** GitHub Actions の `auto-blog-post.yml`
(週2回・火金 09:00 JST)は生き続けており、最終実行は 9/25。2026-09-28 に停止した。

★**この仕組みには構造的な問題があった。**

```
生成 → 変更があれば git push origin main → Vercelが自動デプロイ
                                              ↑ここで公開される
blog-gate.yml は push の「後」に走る → 落ちてもCIが赤くなるだけ
```

つまり**門は公開を止められていなかった。** 事後の警報でしかない。
今日見つかった誤り(捏造引用・出典と逆の結論・条件の欠落)が公開され続けたのは、この構造による。

### 再開するなら
全自動には戻さない。hiroo-open 側の方針(「★院長名義で出るものは、必ず人が確認してから投稿する」)
と同じ形にする。

1. 生成は **`draft: true` の下書きまで**(門は draft を対象外にしてある)
2. **PR を作る**。main へ直接 push しない
3. PR で門(`blog-gate.yml`)が走り、**落ちたらマージできない**
4. 人が「2. 人が読む」を通してから `draft` を外してマージ

★3が肝心。門を「公開の前」に置かないと、門ではなく警報にしかならない。

## 1. 機械にかける(10秒)

```bash
cd ~/Desktop/claude1/webpage.new
python3 scripts/compliance/regression.py   # 門そのものが壊れていないか
python3 scripts/compliance/check_blog.py   # 全記事(1本なら path を渡す)
```

落ちるもの: 台帳(`scripts/compliance/pmid_titles.json`)に無いPMID / 本文の (姓, 年) が参考文献のPMIDと合わない /
参考文献の DOI・PMC・巻号 / MDXが500になる記法(`<Link>` `:::` `{.class}`) / frontmatter欠落・規定外カテゴリ。
警告: 「臨床試験で」「研究で示され」等があるのにPMIDが無い(型B)。
GitHub Actions `blog-gate.yml` が content の push ごとに同じものを走らせる。

**新しい文献を使うとき**: PubMed で確認 → `pmid_titles.json` に登録(title/year/journal/authors/pubyear)。
参考文献の書き方は **`題名. 誌名. 年. PMID: 番号`** だけ。著者・巻号・DOI は書かない。

## 2. 人が読む(1本 10〜15分)

引用ごとに PubMed で抄録を開いて確かめる。判定の型は
`~/Desktop/claude1/hiroo-open/the-skin-atelier/docs/校閲の型.md`(型A〜K)。要点:

- 型A 主題と結論の向きが合っているか(出典に本文を合わせる。逆はやらない)
- 型B 数値・比率・「研究で」の枕詞に出典があるか(定性的な助言は不問)
- 型D 単位・人数・追跡の終わりの時点
- 型E 薬剤・サプリの効果を書いたら主な副作用と注意
- 型I 著者の所属に企業名(サプリ・検査会社)があれば本文に書く
- 型J 人数と研究の型を書く(「報告されています」で終えない)
- ガイドラインは「平均の比較」。絶対則のように書かない。読者の努力を否定しない

★判定を下す前に必ず原著を読む。監査する側も間違える。

### ★最短で誤りが見つかる探し方(2026-10-01 実証・10件で10件)

**「参考文献にPMIDがあるのに、本文がその著者名・内容に一度も触れていない」記事を探す。**
これは機械で探せる。32本の監査で、この型に当てはまった文献は**10件すべて**で
出典の最重要の所見が本文から落ちていた。落ちていた例:

- PGT-A の正倍数性結果の陽性的中率 50〜60%
- 精子形態の予測能の低さ(「感度・特異度がとても低い」)
- ミオイノシトールの出典が記事の主題について何の結論も出していなかったこと
- 胚盤胞まで待つと**移植できる胚がゼロになる割合が2〜4倍**(OR 2.50)
- CA-125 の**感度 0.40**(= 内膜症があっても約6割が正常範囲)

```bash
# 本文がPMIDを参考文献にしか書いていない記事を洗い出す
for f in src/content/blog/jp/*.mdx; do
  # 参考文献より前の本文に著者名が出てこないものを疑う
  :
done
```
手で見るなら、参考文献の各行の第一著者名を本文側で grep して、
**1件もヒットしない文献を優先して照合する**。

### ★型L「差がない」と「分からない」を取り違えない(2026-10-01 追加)

信頼区間が1をまたいでいることは、**差がないことの証明ではない**。
人数が足りていないだけのことが多く、レビュー自身が
`too imprecise to be informative` / `we are uncertain` / `the power to detect
small differences was low` と書いている。これを「有意差は見られませんでした」
と書き換えるのは、**読者に「決着がついた」と誤解させる**ので型Aと同じ扱いにする。

- ✗ 「排卵前と排卵後で有意差は見られませんでした」
- ○ 「どちらが良いかを判断できる証拠がない(人数が足りず不精確)」

逆向きの取り違えも起きる。**「有意差なし」と書くべきところを「同等」と断定する**のも同じ誤り。

### ★GRADE の確実性を数字と一緒に必ず書く

オッズ比だけを書いて確実性を書かないと、「とても低い」確実性の数字が
確定した事実のように読める。観察研究のメタ解析では、
**交絡を調整したら消える項目がある**(例: ホルモン補充周期と前置胎盤・早産)。
調整前の数字だけを引かない。

## 出す前・出した後に必ず走らせるもの（2026-10-01 追加）

```bash
python3 scripts/compliance/check_blog.py          # 門
node    scripts/compliance/mdx_compile_check.mjs  # ★MDXが本番で500にならないか
npm run build                                     # ビルド
git push origin main
bash    scripts/compliance/verify_deploy.sh       # ★反映確認＋本番の全記事ステータス
```

### ★`npm run build` が通ることは「ページが開ける」ことを意味しない

ブログページはサーバーレンダリング（`ƒ /blog/[slug]`）なので、**MDXのコンパイルは
リクエスト時に起きる**。ビルドが通っても本番で500になる。

2026-10-01、`<0.7 ng/mL` のように**不等号の直後に数字**を書いた6本が壊れ、
うち2本が実際に本番で500を返していた（MDXが `<0` をJSXの開始と解釈する）。
`P < 0.001` のように空白を挟めば安全。門でも止めるようにしたが、
`mdx_compile_check.mjs` は実際のコンパイラで全件を検証するので、
正規表現で拾いきれない記法も確実に捕まる。

### ★反映確認の目印は「そのコミットでしか出ない文字列」にする

前のコミットで入った文字列を目印にすると、**まだデプロイ中の段階で
「反映済み」と誤判定する**。このミスを1セッションで3回繰り返した。

`verify_deploy.sh` は直近コミットの追加行から目印を自動で選ぶので、
手で目印を決めないこと。

### ★デプロイ後は全記事のHTTPステータスを見る

1本ずつ抜き取るのではなく、公開記事すべてを確認する。
壊れたページは、該当記事を開かない限り気づけない。
